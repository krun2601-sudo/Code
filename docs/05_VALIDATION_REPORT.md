## 2. 静态预检保留警告

现场继承配置的四套内参目前字节级相同、畸变系数全零、视频时延全零。这些数值可能只是尚未完成逐机标定，不应被论文当成已验证事实。`calibration_verified: true` 也是软件门，不等于独立测量证据。

正式 experiment 预检还要求：

- 四设备实时遥测新鲜、连接正常；
- `zoom_known=true`、`zoom_stable=true`、倍率 10×；
- 四路新鲜可用 1920×1080 帧，且分辨率与各自内参一致；
- 最近命令已发送且 ACK 成功；
- `reachable_count=384`、`reachable_ratio=1`；
- 有日期化站姿、逐机内参、固定倍率、视频时延证据；
- 四设备时间模型齐全并经独立测试集审核。

## 3. 计划一致性

主计划 ID 为 `ralhil-2401-8b`。24 个配对组均包含五个方法，组内共享 `instance_seed`、`injection_seed`、条件 JSON、硬件配置哈希和 pair-frozen 哈希；每种方法使用不同 `solver_seed` 与完整配置哈希。各方法在组内 1–5 顺序位置的出现次数差不超过 1。

该计划是用于审查设计结构和随机化合同的阶段一草案。由于当前 `execution_model.status=uncalibrated`，它不是正式主实验执行清单。commissioning 后须先审核模型、更新私有配置中的模型路径和标定证据，再用同一生成器重建计划及其 120 份 overlay；此时产生的新哈希才是正式实验出处。正式配置已设 `strict_measured_model: true`，Measured-CML-H 与 EA-CML-H 在模型缺失或不完整时会直接拒绝启动。

三条件的冻结实现为：

- `nominal`：无主动注入；
- `heterogeneous_delay`：只延迟策略确认事件时钟，不阻塞线程或看门狗；
- `pause`：按预定时段屏蔽一台设备的策略可用性，旧命令按 TTL 失效，不调用 SDK 故障接口。
