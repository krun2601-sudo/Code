# ZR10协同覆盖算法V2：理论、证据链与实验门槛

## 1. 研究对象与边界

研究对象是四台网络化视觉传感器对固定三维区域的首次有效覆盖。没有目标真值时，不把覆盖率解释为真实无人机检测概率。若目标在384个等体积评估单元中均匀出现，且到达某单元的首个有效观测即可发现目标，则首次覆盖时间对应发现延迟。

旧42次运行仅用于暴露算法和日志问题，不进入V2的确认性结论。V2正式证据只来自算法、模型、配置和分析脚本冻结之后的新实物运行。

## 2. 符号与优化目标

- \(M=384\)：冻结的评估单元数；
- \(T_i\)：单元 \(i\) 的首次有效观测时间；
- \(H=60\,\mathrm{s}\)：固定评价时域；
- \(\Pi\)：四台设备的有序视场任务集合；
- \(\bar T_i(\Pi)\)：按分档执行时间上界递推得到的首次覆盖上界；
- \(\bar T_{95}\)、\(\bar T_{100}\)：未截断的95%与100%覆盖完成时间上界。

主目标为

\[
\overline{\mathrm{UAC}}_H(\Pi)
=\frac{1}{M}\sum_{i=1}^{M}\min\{\bar T_i(\Pi),H\}.
\]

代码中的 `PlanObjective.uac_h_s` 只对UAC作 \(H\) 截断；`t95_s` 和 `t100_s` 使用未截断的完成时间。这样，T100约束不会因固定评价时域而退化为恒等式。

V2以完整MAG路线为保底解，接受候选解的必要条件为：

\[
\overline{\mathrm{UAC}}_H(\Pi')
<\overline{\mathrm{UAC}}_H(\Pi)-\varepsilon,
\qquad
\bar T_{100}(\Pi')\leq \bar T_{100}(\Pi_{\mathrm{MAG}})+\varepsilon.
\]

T95、总角运动量与负载离散度用于确定性候选排序和审计，不以加权和改变UAC的主目标地位。

## 3. 四项可核验结论

### 命题1：覆盖证据可靠性

若一个单元被记为已覆盖，则日志中存在同一次任务的ACK、稳定姿态、新鲜图像帧和实测姿态投影视场。帧的主机侧曝光时刻估计与姿态样本时刻之差不超过冻结的 `frame_pose_max_gap_s`，单元位于按该姿态重新投影的视场内。

这是有界时间对齐条件下的证据结论，不等同于相机硬件同步。实现对应 `_collect_frame`、`_complete_task` 和 `coverage_confirmed` 事件；分析器拒绝缺少帧号、实测姿态证据模式或超出同步界的运行。

### 命题2：完整性

若鲁棒候选视场的并集覆盖全部评估单元，设备最终恢复，且每个下发任务最终完成ACK—稳定—新帧链路，则每次有效完成至少确认一个尚未覆盖单元，或结束一个已被其他视场覆盖的冗余任务。任务集合有限，因此算法在有限次有效完成后达到完整覆盖。

该结论依赖设备最终恢复和指令最终完成，不对永久断连给出无条件保证。

### 命题3：初始规划的MAG非退化性

正式MAG和V2内部MAG保底解使用相同的鲁棒候选视场、初始姿态、名义MAG构造规则和完整构造开关。V2始终保留该可行解，并只接受严格降低鲁棒UAC且不突破MAG未截断T100上界的候选。因此

\[
\overline{\mathrm{UAC}}_H(\Pi_{\mathrm{V2}})
\leq\overline{\mathrm{UAC}}_H(\Pi_{\mathrm{MAG}}),
\qquad
\bar T_{100}(\Pi_{\mathrm{V2}})
\leq\bar T_{100}(\Pi_{\mathrm{MAG}}).
\]

每次初始规划在 `plan_audit` 中保存基线/最终目标、候选操作计数、拒绝原因和布尔验证结果；分析器再次计算并核验不等式。

### 命题4：事件修复非退化性

故障时，已经确认和正在执行的任务保持不变；健康设备原队列不重排。只有故障设备独占的未完成单元可以通过新增视场转移给健康设备。保持原队列构成在线保底方案。修复仅在预测剩余UAC改善超过冻结阈值且预测剩余T100不增加时实施，否则记录 `replan_noop`。

分析器逐次核验 `replan_applied` 的延迟改善、T100约束和接受判据。实际收益另由恢复前的 `reassigned_coverage_confirmed` 事件证明。

## 4. 执行时间上界

单次任务时间从首次相关速度指令发出开始，到实测姿态稳定且取得到位后的新RTSP帧为止。点预测模型包含非负截距、方位正/负方向、俯仰上/下方向项以及双轴同时运动指示项；小、中、大转角分别使用互不混用的单侧校准余量。

训练、校准、测试必须来自三个不同的完整实物运行。`fit_execution_model.py` 会拒绝同一运行同时出现多个集合标签。正式模型还必须包含：

- 四台设备的非负系数；
- 小/中/大转角的校准样本数、有限样本秩和上界余量；
- 校准运行得到的方位、俯仰到位误差上界；
- 模型文件SHA-256。

理论只作条件表述：若每次实际任务时间不超过所用上界，则实际UAC与T100不超过相应规划上界。

## 5. 从开发到正式实验

1. 运行四路RTSP只读稳定性测试，每路连续解码至少300秒，最大解码帧间隙不超过2秒。
2. 生成60轮/设备的小、中、大转角序列。训练、校准、测试分别使用三个独立覆盖层执行，不能在同一会话中混合。
3. 拟合分档时间模型，把模型给出的到位误差上界写入V2私有配置，并冻结模型哈希。
4. 生成六次开发运行：V2、MAG、实测静态规划的标称运行；V2和实测静态规划的暂停运行；另一次V2标称重复性运行。
5. `audit_v2_readiness.py` 同时通过视频、模型、开发UAC/T100和有效修复门槛后，才允许生成50次正式计划。
6. 正式计划包含10个区组，每区组3次标称运行和2次暂停运行。任一运行因预注册原因无效时，原始目录保留，整个区组作废并重做；同一区组连续两次失败后批处理锁定，要求排查后使用新的审计控制目录。

正式分析必须提供批处理状态文件，以唯一选定每个计划行的有效尝试。被作废的原始目录仍进入拒绝报告，不会被删除或静默覆盖。

## 6. 论文启动判据

`analyze_runs.py` 为正式V2计划额外输出 `v2_decision_gates.json`。只有以下条件全部为真，`paper_start_allowed` 才为真：

- 10个区组完整；
- 标称V2相对MAG的配对UAC差值中位数小于0，bootstrap 95%置信区间上界小于0，单侧精确符号检验 \(p<0.05\)；
- V2/MAG配对T100比值的bootstrap 95%置信区间上界不超过1.05；
- 暂停引起的UAC增量采用配对差分中的差分，其95%置信区间上界小于0；
- 至少一次重分配覆盖在原设备恢复前得到实测确认。

当前阶段只完成软件、协议和离线审计。实物开发运行、正式50次运行及论文改写均未启动。
